# QVAC integration evidence (Developer A)

## Installed API and runtime

- Official [QVAC JS/TS SDK documentation](https://docs.qvac.tether.io/sdk/js-ts-sdk/) specifies `@qvac/sdk` and Node.js >=22.17. The npm tarball was inspected at pinned version `0.21.1`.
- This repository pins `@qvac/sdk@0.21.1` and uses the local `node@22.17.0` binary. The machine's global Node 22.13.1 is too old.
- `QvacInterpreter` uses SDK `loadModel()` and `completion()` with the local `QWEN3_1_7B_INST_Q4` model (1,056,782,912 bytes). Its weights are cached under `~/.qvac/models/`; model content is public, and no application prompts or wallet data were uploaded for inference. No cloud model is configured.
- The SDK's Bare worker needed a direct `b4a@1.9.0` root dependency in this npm workspace. Without it the worker exited at startup with `MODULE_NOT_FOUND: b4a` imported from `bogon/index.js`. The isolated SDK install had root `b4a` and worked.

## Reproducible checks

From repository root, with dependencies installed:

```sh
./node_modules/node/bin/node --import tsx --test apps/local-client/test/qvac.test.ts
npm run smoke:qvac
```

On 2026-10-17 the unit tests passed (3/3), the repository typecheck passed, and the real smoke exited 0 after local inference. For the synthetic goal to sell 100 X for at least 100 DUSD with a maximum fee of 1000 sats, the model returned exact pinned asset keys, human amount strings `100`/`100`, `maxFeeSats="1000"`, `allowBtcSale=false`, and diagnostics `provider="qvac"`, `model="QWEN3_1_7B_INST_Q4"`, `durationMs=1084` on a cached run. The result was generated by QVAC; the script does not contain canned answers. The model echoed the full goal into `clarification` despite extracting all fixed-order fields, so deterministic code discarded only that exact echo. The resulting `clarification` was null and the fixed-order draft was usable for user review.

A harder synthetic goal containing “сохранить минимум 50% X” was misread as `minAmount="50"` instead of `minPercent=50`. The adapter now rejects any percent-bearing goal without a parsed `minPercent`; the user must correct it manually. **Do not treat a successful model call or schema-constrained JSON as a safe order.** The local client must validate asset keys, decimal amounts, private balance policy and explicit user approval before publishing. The model has no signing or settlement tools.

`QvacInterpreter.health()` loads the model before reporting `available=true`, so the first call may download weights and take longer. A failed load reports unavailable without exposing prompts. `interpret()` caps input size, constrains output to JSON, validates it with `AiIntentSchema`, applies an inference deadline and returns diagnostics without private inputs. `dispose()` unloads the model for process shutdown and smoke exit.

The official SDK [text generation guide](https://docs.qvac.tether.io/sdk/ai-capabilities/text-generation/) documents `completion().final`, `captureThinking` and structured response formats. The 0.21.1 combination was verified locally; the hackathon notes mention earlier structured-output failures on other versions, so the pinned version matters.

## Docker Linux CPU check — 17 October 2026

The root Compose stack was built and started on Docker Desktop Linux arm64 with 12 virtual CPUs and approximately 8 GB of VM RAM. Runtime base: `node:22.17.0-bookworm-slim`; `libatomic1`, `libgomp1` and CA certificates are installed. Docker sets `QVAC_DEVICE=cpu`, which selects `device: 'cpu', gpu_layers: 0`; native execution retains its existing automatic backend selection. The SDK's packaged Bare binary initially lacked executable permissions, so the image build sets mode 0755 before switching to UID 1000.

The first startup downloaded the actual 1,056,782,912-byte model into the named QVAC volume and loaded it successfully. A single preparation process populates the shared cache before starting A/B/C, because the SDK's download deduplication is per process. This avoids concurrent downloads deleting one another's incomplete files. Subsequent restarts reuse the weights.

An actual `POST /api/interpret` through host port 4101 produced a usable X → DUSD draft with amounts 100/100, fee cap 1000 sats and BTC sale disabled in **8.96 seconds**, including that profile's initial model load. All three profile processes subsequently reported QVAC available concurrently within the same 8 GB Docker VM. This checks this arm64 machine only; Linux amd64 and GPU inference in Docker were not exercised.

The documented `docker compose exec runtime npm run smoke:qvac` also exited 0, with 3,719 ms of inference diagnostics and the expected synthetic intent fields.

The same running stack passed direct and three-party matching, explicit mock `UNSUPPORTED` settlement, auth/Origin/Host rejection, static asset serving and SPA fallback. All 41 tests passed inside the Linux image. Restart preserved pairing-token hashes, both demo trade records and API availability. No real wallet signing or RGB settlement was performed.
